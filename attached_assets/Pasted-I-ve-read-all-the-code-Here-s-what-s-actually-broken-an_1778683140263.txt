I've read all the code. Here's what's actually broken and the exact fixes:
Issue 1 — Charity field not working: The charityId form field is controlled by both field (from react-hook-form) AND a separate charitySelection state. But the Select component uses value={charitySelection} (the state) while the form schema drives validation. This split control means selections don't register properly. The "Other" path is already coded correctly in onSubmit — it just needs the UI wiring fixed.
Issue 2 — Stripe onboarding link fails: The handleOnboardClick function opens a blank tab first (window.open("")), then tries to redirect it in onSuccess. Popup blockers often kill or detach that blank tab reference, so onboardTabRef.current is null or closed by the time the URL arrives. The fix is to get the URL first, then open the tab.
Issue 3 — Stripe sandbox: This is a Stripe Dashboard configuration issue, not a code bug. The code in routes.ts is correct. I'll write you the exact steps below.

Fix 1: Stripe onboarding link
Replace the handleOnboardClick function (around line 90) with this:
typescriptconst handleOnboardClick = async () => {
  try {
    const res = await fetch("/api/stripe/connect/onboard", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ origin: window.location.origin }),
    });
    const body = await res.json().catch(() => ({}));
    if (!res.ok) throw new Error(body.message || "Failed to start onboarding");
    window.open(body.url, "_blank", "noopener,noreferrer");
  } catch (err: any) {
    toast({ title: "Couldn't start onboarding", description: err.message, variant: "destructive" });
  }
};
Also find the two other places that call onboard.mutate() directly (the two buttons inside the alert boxes at the bottom) and replace each onClick with onClick={handleOnboardClick}. The onboard mutation and onboardTabRef can be removed entirely since they're no longer needed.

Fix 3: Stripe live mode (not a code issue)
Your code is fine. Stripe is keeping you in sandbox because your platform account isn't activated for live mode yet. Do this in order:

Go to dashboard.stripe.com and make sure the Test mode toggle is OFF (top right)
Look for the "Activate your account" banner — fill out your business details (identity, bank account, business description). This is required before any live payments or Connect onboarding work
Go to Connect → Settings and make sure Connect is enabled
Under Connect → Settings → Platform profile, fill in your website (brushbids.com), product description, and support email — Stripe will reject accountLinks.create calls if this is blank, which is exactly the error you're seeing
Once all that's done, swap your Replit secrets from pk_test_ / sk_test_ to your pk_live_ / sk_live_ keys

Step 4 is almost certainly the direct cause of the onboarding link failing in live mode — the platform profile being incomplete is what Stripe returns as the vague error your backend is already catching.
